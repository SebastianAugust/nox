You are working on **Nox**, Bas's personal Windows desktop pet assistant (Tauri v2 + React + TypeScript, SQLite via tauri-plugin-sql, Ollama llama3.2:3b). Personal app, not for distribution. The Night Lair redesign is already done; keep its look and tokens.

## Rules (read first)

6. **Do not `git commit` or `git push`.** Bas commits himself. Work task by task; before moving on, `npx tsc --noEmit`, `npm run build`, `npm test`, and `cargo check` (in `src-tauri`) must be green.

## Tasks

### P1 — Secrets in Credential Manager
- Add the `keyring` crate. Rust commands: `secret_set(name, value)`, `secret_exists(name) -> bool`, `secret_delete(name)`. **No command returns a secret value to JS.**
- Names: `notion_token`, `telegram_bot_token`.
- Settings → Integrations: password-style input to paste a token, shows only "Saved" or "Not set", plus Remove.

### P2 — Rust HTTP layer
- Shared reqwest client (timeouts 15 s, sane User-Agent `Nox/0.x`, no email or personal data in headers).
- Typed errors mapped to short user-facing messages (no token, 401, 429, offline, timeout). Never include the token in an error or log line.

### P3 — Notion sync (read-only)
- Settings: `notion_assignments_db_id`, `notion_courses_db_id` (accept a full Notion URL or raw ID and extract the ID).
- Property mapping config (title, due date, course relation, status, done flag) with sensible fallbacks by property type, so renamed columns don't crash the sync. Show a clear message when a mapping fails.
- Rust: query the database with pagination, respect rate limits (max ~3 req/s, retry on 429 using Retry-After).
- Upsert into `notion_assignments` and `notion_courses` (new migration only if columns are missing). Keep `notion_id`, `last_synced_at`. Mark rows removed or completed upstream instead of hard-deleting.
- Sync on app start, every 30 minutes, and via a manual "Sync now" button. Integrations page shows last sync time, row counts, last error.
- Offline or failing sync must never block the app; the last good data stays visible.

### P4 — Weather (Open-Meteo, no key)
- Rust command: current + today's forecast (temp, feels-like, rain probability, weather code, sunrise/sunset).
- Cache in `weather_cache` with 30-minute TTL; on failure serve the cache and mark it stale.
- Small weather chip on Home. Pet may mention rain only inside the briefing or deadline context, not as random chatter.

### P5 — Daily briefing
- Setting `briefing_enabled` (default on) and `briefing_time`.
- Rule-based content (works with Ollama off): date, weather summary, today's deadlines, overdue items, today's todos, due habits, reminders today.
- Optionally ask Ollama for a 1–2 sentence friendly opener with a hard timeout and a fallback to a static opener. The factual list is never generated by the LLM.
- Fires once per day at the set time. If the app starts after that time and today's briefing has not shown, show it once on startup (store `last_briefing_date`).
- Delivery through `deliver.ts` (held during focus like other non-reminder kinds), plus Telegram when enabled (P8).

### P6 — Deadline radar
- Home widget: assignments due in the next 7 days plus overdue, sorted by due date, with course name and a plain urgency label (overdue / today / tomorrow / N days).
- Nudges at 3d / 1d / 3h through `deliver.ts`, deduped in a new `nudges_sent` table (assignment id + threshold), respecting focus/DND rules. Never repeat a nudge after restart.
- "Start focus" action on a nudge launches the pomodoro for that assignment via the existing events.

### P7 — Rigid command parser
- Pure TS module `src/lib/commands.ts` (no UI imports) with unit tests. Commands (id + en aliases, case-insensitive):
  `/tugas` (list upcoming), `/tugas <n>` (detail), `/todo <text>` (add), `/todo list`, `/done <n>`, `/ingat <time> <text>` (reminder; support `10m`, `2h`, `18:30`, `besok 08:00`), `/fokus [menit]`, `/stop`, `/status`, `/cuaca`, `/bantu`.
- Returns structured results plus a plain-text rendering. Unknown commands get a short help hint.
- Wire into the pet chat input: anything starting with `/` goes to the parser, never to Ollama. Everything else keeps the current LLM chat behaviour.

### P8 — Telegram bot (phone ↔ Nox)
- Rust long polling (`getUpdates`, timeout ~30 s), owned by the **pet window** (single poller). Persist the update `offset` so nothing is processed twice. Back off on errors; stop and show "Token invalid" on 401. Split replies over 4096 chars.
- **Allowlist by pairing:** Settings shows a 6-digit pairing code (expires in 10 minutes). Bas sends `/pair <code>` to the bot; Nox stores that `chat_id` and ignores every other chat silently. Include an Unpair button.
- Paired chat can use all P7 commands. Free text goes to Ollama as normal chat, with a "Nox is thinking…" typing action; if the PC or Ollama is slow, reply with a short notice instead of failing silently.
- Push to Telegram (each toggleable in Settings): reminders, morning briefing, deadline nudges.
- **No command may run shell commands, read arbitrary files, or expose anything beyond the listed commands.**
- Messages received while Nox was offline are handled on start, but reminders never rely on Telegram as the only channel.

### P9 — Settings, i18n, docs
- Settings → Integrations page: Notion, Weather (location), Telegram (token, pairing, toggles), briefing time. All strings in `en` and `id`.
- Update `docs/ARCHITECTURE.md` (new Rust commands, events, tables, data flow, security notes).
